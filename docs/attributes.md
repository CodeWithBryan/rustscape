# Native player attribute persistence

`server::player::attributes` implements the GameAttributes store and the
PlayerSaveParser.parseAttributes / PlayerSaver.saveAttributes profile sections.
It supports typed integers, longs, shorts, bytes, booleans, strings, shared
mutable attribute locations and opaque native objects. Opaque objects retain
their identity and provide their current display string when saving.

The implementation preserves the original persistence behavior:

- Setting strips one leading `/save:` and adds the key to the saved list only
  if absent. Getting strips every `/save:` marker. Removal uses the exact key,
  removes one saved-list occurrence, and retains expiration metadata.
- JSON loading appends saved-list entries, including duplicates. Expiration is
  checked only while loading, with `expiry < now` skipped and equality accepted.
  Getting an attribute does not expire it. Expiration writes and saved-list
  additions survive a later value conversion error.
- Unknown JSON types produce null values and the original warning text. Saving
  skips null values; an empty saved list leaves an existing root untouched,
  while a nonempty list containing no values writes an empty attribute array.
- Bytes use the basic Base64 alphabet. Loading validates the entire encoded
  string and reads its first decoded byte, preserving Java's padding and unused
  trailing-bit rules. Strings and locations preserve the original coercion,
  numeric parsing, whitespace and signed packed-coordinate behavior.
- Null map keys/values and nullable expirations are represented explicitly.
  Ordinary lookups borrow their key and avoid a replacement-string allocation
  when no `/save:` marker exists. Expensive world work and event dispatch are
  outside this store.

The legacy loader reads the literal configured prefix plus filename, validates
the XML document before applying any attribute values, and visits GameAttribute
elements in document order. Conversion failures retain earlier mutations and
are returned as diagnostics, matching the original caught-error behavior.
Missing files are a separate outcome. The deprecated dump method remains empty.

The native loader covers tested UTF-8, UTF-16, ISO-8859-1, Windows-1252 and
Shift_JIS files, nested nodes, qualification, character/internal entity
references, attribute whitespace and malformed-document behavior. It uses
roxmltree and encoding_rs. External DTD/entity resolution and DTD default
attributes are not implemented. Complete JDK XML/charset behavior and arbitrary
encodings remain unverified.

## Verification

`fixtures/attributes/` contains **503 original JVM sequences** and source hashes.
The oracle compiles GameAttributes unchanged, extracts the profile methods
verbatim, and uses original LocationHash/fromString code with a coordinate
holder. Player association, clock and logging are explicit adapters. It records
the exact XML file bytes generated by the JVM; native tests consume those bytes
instead of using a native encoder to generate their own inputs.

Tests compare typed state, saved-key order, expiration state, current clock and
clock-read count, return/errors, warning text, caught legacy-file errors and saved
JSON. Every byte value and relevant Base64 boundaries are covered. Temporary
files are isolated under ignored runs directories and removed after use.

```powershell
cargo test -p rs09-server --test attributes
cargo xtask attributes-oracle --check --java-home PATH_TO_JDK_11
```

Full profile file parsing/saving, Entity attribute events and content/world
integration remain pending. The JSON API accepts structured serde_json values;
full original raw-JSON parsing and arbitrary Java object semantics are separate
work. Native location support here covers attribute data/identity, not a complete
world geometry class. Configured login continues to stop at its existing
metadata boundary until the complete profile and world-entry path is ported.
